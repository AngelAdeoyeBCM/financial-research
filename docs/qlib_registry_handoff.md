## Context
This document covers two things: how QLib seeds enums and definitions and turns ids into objects, and which parts of that design to adopt.

## 1. How QLib does it

### Layer 1: enums (`Serialization\DynamicEnum.cs`)
- **One global registry** of class key → UPPER key → instance, interned and matched case-insensitively. Constructing a value registers it, and a duplicate key throws.
- **Seeded values** are `static readonly` fields in each enum class (e.g. `CurrencyCode.USD`). The code doesn't load any enum list from config.
- **Open vs closed** is decided by the parser registered in `Identifiable\IdentityTypes.cs`:
  - Open: `CurrencyCode` (`cc`), `ReferenceIndex` (`ref`) and `RateIndex` create unknown values on first parse.
  - Closed: `BondClassification` (`bnd-clss`) throws on unknown values. So does `CountryCode` (`cn`), unless the value was registered earlier.
- **Values added while loading.** Parsing `ccy[AMD]`, `idx[AMD,IBOR]` and similar files creates new enum values, so the bundle effectively extends the enums.
- **Countries come from the Zenith ref-data service:** `CountryCode.DynamicParser.Parse(iso2)` plus `RegisterAssociation(NAME, code)`.
- **Aliases** live in per-source parser chains, not in the registry:
  - `AltTextFormatter` and `GroupFormatter`, e.g. `ReferenceIndex.SinaiParser` maps EuroSTR→ESTR and FEDFUNDS→OIS.
  - `Seniority` has Markit and Credit parsers.
  - Field names can differ from keys: `USCPI` has key `CPURNSA`, `FEDFUNDS` has key `FF`.
- **Quirk:** caching formatters also cache failed parses.

### Layer 2: identifiers (`Identifiable\IdentityType.cs`, `IdentityTypes.cs`)
- **One grammar:** `type[required fields..., key:value...]`, e.g. `idx[USD,SOFR]`, `fx[EUR,cc:USD]`, `bndcnv[US,Infl,USD]`, `swp[AUD,maturity:3M,fix-freq:Q]`.
- **Type registration:** about 150 types are registered in one static constructor. Each declares its required child types, e.g. `bndcnv = [CountryCodes, BondClassifications, CurrencyCodes]`.
- **Values:** an `IdentityEnum` value, a `PropertyIdentifier<T>` (tenor, strike, ticker, isin), or a nested `StructureIdentifier`. All are interned.
- **Matching:** `*` is a wildcard. `Matches` is a subset match: a pattern matches any id that has at least the pattern's parts.

### Layer 3: definitions (`Market\Definitions\ADefinition.cs`)
- **Each definition is a class with static property archivers** (`FormattedPropertyArchiver(name, parser)`). These handle required fields and defaults, and a default may depend on a field read earlier (`YldDcc ?? Dcc`, `BondType ?? ccy`).
- **The identity is computed from the fields** by `GenerateIdentity()`, not taken from the file name.
- **Files:** each definition is one file named by its id (`:` is written `=` in the file name). The first line is the C# type, followed by `&0` / `*1` anchors (`Serialization\Archivable\YamlArchive.cs`).
- **Cross-references** such as `RateIndex: idx[AED,EIBOR]` are resolved eagerly through `LazyDefinitionFormatter` → `Get<T>`.
- **Cycles** (idx ↔ flt, ccy ↔ idx) are broken by calling `RegisterDefinition(this)` before reading back-references (`RateIndexDefinition.cs:380`, `CurrencyDefinition.cs:287`, the latter commented "bootsrap hack").

### Layer 4: factories, which are QLib's "builders" (`Identifiable\AFactory.cs`, `IDefinitionFactory.cs`)
- **Factory lists:** `market_definitions.cfg` lists domain ymls (`ccys.yml`, `insts.yml`, …). Each yml is an ordered list of `{FactoryClass, WildCard, params}`, loaded by reflection.
- **Factory selection** for an id:
  - domains are tried in order;
  - within a domain, file factories come first (an exact file overrides code);
  - then pattern factories in yml order, first match wins, from specific to catch-all: `AVG_` → `swp[*,maturity:*]` → `swp[*]`.
  - The factory chosen for each id is cached, including misses.
- **Manager** (`ADefinitionManager.cs`):
  - caches by the definition's own canonical id;
  - records the requested id as an alias when it differs (`swp[USD]` → full canonical swap);
  - keeps building `PrimaryRequirements` until nothing new is needed.
  - A failed build returns null.
- **How factories build:** they parse the id, `Get` the convention definitions it needs, and compose an object. `VanillaSwapFactory` builds `swp[...]` from ccy → idx → `flt` + overrides; `BasisSwapFactory` does the same for `bswp`.
- **Defaults:** catch-all factories (`ccy[*]`, `swp[*]`) and `BondConventionDefinition.Get` build defaults when no file exists. `BND_CONV_FACT` is listed in `insts.yml`, but its class isn't in this source tree, so the fallback in `Get` is what runs.
- **Instances:** a definition is a template without dates. `BuildInstance(point)` turns it into an instance, which is what gets priced.

## 2. What to adopt for incolor's own registries (recommended)
1. **Use the QLib id grammar for ids.** Every market entity keeps a canonical QLib-shaped id (`ccy[USD]`, `idx[USD,SOFR]`, `fx[EUR,cc:USD]`, `bndcnv[FR,Govt,EUR]`, `flt[USD,SOFR,1D]`) that is computed from its fields, as `GenerateIdentity` does. It is checked at load time: the file key must equal the derived id. A small Python parser and formatter for `type[...]` handles this, with the required child types per type taken from `IdentityTypes.cs`.
2. **Keep the enum mechanics simple and explicit.** Mirror QLib's keys (`cc`, `cn`, `ref`, `bnd-clss`, …) with the existing `scripts/sync_qlib_enums.py`. Mark each enum open or closed. Keep aliases in separate per-source maps (`bbg`, `sinai`, `research`) that point at canonical values, so the canonical set stays clean. Don't cache failed lookups.
3. **One seed file per definition, with typed references.** References are full ids. A two-pass load (read everything, then resolve references) replaces QLib's register-early hack and makes dangling references a load error.
4. **Factories as an ordered pattern list.** Exact seed files first, then pattern factories from specific to catch-all, which build defaults (bndcnv from ccy conventions; swp/flt from idx). Requested ids alias to canonical ids. This is the layer the resolver targets: text → candidate id → factory checks and canonicalises it.
5. **Seed from QCL once, then own the data.** A one-off import script turns the bundle's ~980 files into incolor seed files and records the QCL version they came from. A diff script compares them against later QCL drops, so the user decides what to take.
6. **Ref-data gaps stay incolor's own registries.** Countries, equity indices, futures roots and issuers aren't in the bundle, so the existing YAML registries (geography, `eqidx`, futures roots) remain the seed for these.

## 3. Country and currency in detail (current focus)

### Country: `Market\Instrument\Country.cs`, `CountryData.cs`, `ICountry.cs`, `Market\Enums\CountryCode.cs`
- **Enum** `CountryCode` (`cn`):
  - About 35 hard-coded values, plus specials: `SNAT` (supranational), `MULT` (multinational), `ZZ` (unknown), `EU`, `M1`, `Invalid`.
  - `Parser` = the registry, then a long-name alias table. It is closed. `DynamicParser` creates values.
- **Definition** `cntry[CC]`: `CountryData` has only four fields: `CountryCode`, `CurrencyCode`, `Name`, `Region`. Its id is `cntry[code]`.
  - `Currency` is resolved lazily from `CurrencyCode`.
- **Seeding** comes from ref data, not files. `CountryDefinitionFactory` has `RequiresRefData` set.
  - When it reads its config, it pulls every country from Zenith (`ZenithCountryExtractorFactory.cs`). Rows without ISO2 or ISO currency are skipped.
  - For each country it calls `CountryCode.DynamicParser.Parse(ISO2)` and `RegisterAssociation(NAME, code)`.
  - Mapping: `ShortName` → `Name`, `Continent` → `Region`, `ISOCurrency` → `CurrencyCode`.
  - Only the dummy entries `MULT`, `SNAT` and `ZZ` are files.

### Currency: `Market\Instrument\CurrencyDefinition.cs`, `CurrencyCode.cs`
- **Enum** `CurrencyCode` (`cc`):
  - About 70 hard-coded values, including metals XAU/XAG/XPD/XPT and units CLF/UDI/MXV.
  - Hard-coded groups: `G10`, `XcCcys`, `StdCcys`, `SwpoCcys`, …
  - `Parser` is open. `StaticParser` is closed.
- **Definition** `ccy[CCY]`: 43 properties (full grouped table below). All are optional except `CurrencyCode` and `RateIndexes`. Defaults are applied in the constructor or on read.
- **Factory** `CurrencyDefinitionFactory` (`ccy[*]`): builds a bare dummy currency (`IsDummy=true`) when no file exists.
- **Read-time defaults derived from other fields:**
  - `DefaultIborRateIndex` = the first non-OIS index.
  - `DefaultOisRateIndex` = the first OIS index.
  - `DefaultCountryCode` = the first two letters of the code (USD → US), if that parses.
  - `DefaultPayLegForBasisSwap` = the IBOR default.
  - `BondCurveEOD` = `EOD`.
  - `VarPublicationHoliday` = the IBOR index's pay holiday.
- **Logic on the definition:** `GetDefaultRateIndex(valDate, mat)` returns the reform index after its switch date if it has that tenor; for an overnight tenor it returns the reform, then OIS, then IBOR index; otherwise the IBOR default.

### Where currency information comes from
1. **Hand-maintained `ccy\ccy[XXX]` files in the QCL bundle.** Most properties are typed in here by QLib maintainers. Nothing generates them from a vendor.
2. **Code defaults in `CurrencyDefinition.ReadFromArchive`**, some derived from other fields.
3. **Linked definitions.** `idx[...]` files in `inst\` supply the rate, inflation and commodity indices. A holiday parser supplies holidays (`hols[]` table, built from ref data by `JunkoHolidayFactory` in `data\ref\def_ext.yml`).
4. **External data keyed by currency, not stored on the definition.** Central-bank meeting dates come from `\\bluecrest\cfs\Production\Apps\Risk\Models\Meetings\CentralBankMeetingDatesUnadjusted.dat` (tab-separated: ccy, date[, effective]), loaded by `Market\Tenor\MeetingDatesFileFactory.cs`.
5. **Ignored keys.** Some keys appear in files but the reader in this source revision never reads them: `NaturalCcy` (4 files), `CurveTemplates` (4), `PublishedFamilies` (1), `FixedEffectiveCbDates` (2), `CentralBankEffectiveHoliday` (1), `IsBusinessDayExDividendDays` (1), and `TEST`/`PROD` (sub-blocks under `CurveRebuildsSupportedFor`). The bundle may be newer than this source.
- `CentralBankCode` (FED, ECB, RBA, CBN for Norges Bank…) is stored but not read anywhere else in Core.Src. The meeting logic is keyed on `CentralBankMeetingCurrencyCode` + `MaxNumberOfCentralBankMeetings` (15 = enabled, 0 = off).
- Country note for later: in this bundle `cntry[*]` is served by `CountryConfigExtractorFactory` (QLib.Data assembly, not in source; `data\ref\def_ext.yml`). The Zenith extractor seen in source is in the `BlueCrest.Risk.Market.MDS` stack.

- incolor `Currency` (`src/incolor/ontology/markets.py:119`) has `code` (ISO 4217), `geography_id` and `issuer_id` (the central bank, as an organization). In QLib these correspond to `CurrencyCode`, `DefaultCountryCode` and `CentralBankCode`, the last being a string rather than an entity.
- incolor `Geography` (`geography.py:18`) has `level` and `code` (ISO2). In QLib these correspond to `CountryCode`, plus `Name`/`Region` and currency.
